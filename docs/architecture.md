# 工程结构

当前只提供构建骨架，不实现内存 KV 的存储、命令解析、并发或淘汰策略。

## 模块边界

- `libs/core/include/kv/core/`：KV 核心模块的公开 API。
- `libs/core/src/`：实现和私有头文件，其他模块不直接引用。
- `libs/core/tests/`：核心模块测试，通过 `KV::Core` 链接业务库。
- `apps/cli/`：程序入口，后续负责输入解析、输出和组件组装。

依赖方向：`kv_cli -> KV::Core`、`kv_core_build_smoke -> KV::Core`。
核心库不依赖 CLI。新增业务模块时，在 `libs/` 下建立独立目录和 target。

## 构建约定

- 根 CMake 负责工程声明、测试开关和子目录组装。
- 模块 CMake 显式列出源文件；通过 target 声明编译要求与依赖。
- 公开头文件使用 `<kv/core/文件名.hpp>` 引用。
- `core.cpp` 是空翻译单元，仅用于让静态库构建流程可验证；开始开发时替换为实际实现文件。
- 现有测试只验证构建和启动，不代表任何 KV 功能通过测试；实现功能时补充行为测试。
- 当前安装规则只发布 CLI。需要发布 SDK 时再补充头文件安装、target 导出和包配置。
